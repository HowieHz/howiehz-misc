# BlogsClub 簽到助手

[English](./README.md) | [简体中文](./README.zh.md) | **繁體中文**

## 功能概覽

BlogsClub 簽到助手是一個使用者腳本，提供以下功能：

- 在背景檢查 BlogsClub 當日簽到狀態；
- 手動檢查並開啟 Geetest 驗證碼；
- 驗證碼完成後提交簽到；
- 顯示簽到成功訊息和今日簽到排名；
- 可選的零點搶簽到模式；
- 讀取 HTTP `Date`，校準 BlogsClub 伺服器時間。

腳本不會自動辨識或繞過驗證碼，驗證碼必須由使用者完成。

## 優點

- 自動檢查簽到狀態並提醒，避免忘記簽到；
- 減少多餘請求，降低 BlogsClub 伺服器負擔。

## 快速開始

1. 安裝 [Tampermonkey](https://www.tampermonkey.net)、[Violentmonkey](https://violentmonkey.github.io)、[Greasemonkey](https://www.greasespot.net)、[ScriptCat](https://docs.scriptcat.org) 或其他相容的使用者腳本管理器。
2. 安裝本腳本。
3. 預設設定只在 BlogsClub 頁面檢查。開啟 `https://www.blogsclub.org/` 或其他 BlogsClub 頁面。
4. 開啟使用者腳本管理器選單，選擇 `BlogsClub 帳號：未設定`。
5. 輸入 BlogsClub 電子郵件和密碼。
6. 帳號狀態會先顯示 `已儲存`；成功完成狀態檢查或登入後，會顯示 `已登入`。
7. 需要立即檢查時，選擇 `立即檢查/簽到`。

如果目前頁面不是 BlogsClub 頁面，且「僅在 BlogsClub 頁面檢查」已開啟，手動操作會提示你切換到 BlogsClub 頁面。

## 選單與設定

| 選單項目                        | 預設值   | 作用                                                                                        |
| ------------------------------- | -------- | ------------------------------------------------------------------------------------------- |
| `立即檢查/签到`                 | —        | 立即查詢狀態。尚未簽到時開啟驗證碼並允許手動簽到。                                          |
| `BlogsClub 账号：...`           | `未设置` | 儲存或更新電子郵件和密碼。                                                                  |
| `检查周期：10000 毫秒`          | 10 秒    | 設定背景輪詢間隔，即一次檢查請求完成後要等待多久才發送下一個請求；範圍為 1 毫秒至 24 小時。 |
| `仅在 BlogsClub 页面检查：启用` | 啟用     | 只在 `blogsclub.org` 及其子網域發送檢查請求。                                               |
| `可签到时自动验证码弹窗：关闭`  | 關閉     | 一般輪詢發現尚未簽到時，是否自動開啟驗證碼。                                                |
| `零点抢签到模式：关闭`          | 關閉     | 是否啟用零點前準備驗證碼、零點後提交的流程。                                                |
| `抢签到提前加载验证码：5 秒`    | 5 秒     | 設定在伺服器零點前多久開始準備驗證碼；範圍為 1 至 60 秒。                                   |
| `抢签到提交延迟：500 毫秒`      | 500 毫秒 | 設定伺服器零點後首次提交的延遲；範圍為 0 至 60000 毫秒。                                    |
| `抢签到提交重试次数：10 次`     | 10 次    | 尚未收到成功回應時最多再次提交的次數；範圍為 0 至 100 次。                                  |
| `抢签到提交重试间隔：200 毫秒`  | 200 毫秒 | 設定每次重試啟動的間隔，不等待前一個請求回應；範圍為 1 至 60000 毫秒。                      |

### 帳號狀態

- `未設定`：沒有完整儲存電子郵件和密碼。
- `已儲存`：憑據已寫入使用者腳本管理器的本機儲存，但不代表密碼已驗證成功。
- `已登入`：最近一次狀態檢查或登入成功。
- `登入失敗`：最近一次需要登入的請求失敗，常見原因是密碼錯誤、工作階段失效或網路問題。

密碼只會儲存在使用者腳本管理器的本機儲存中。腳本不會把密碼傳送給驗證碼服務；密碼登入請求只會送到 BlogsClub 登入介面。

## 一般模式

一般模式預設啟用，零點搶簽到模式預設關閉。

### 背景輪詢

腳本依照設定週期呼叫簽到狀態介面。已有有效工作階段時，通常只會發送一次 `signinStatus` 請求；工作階段失效或憑據剛變更時，才會執行登入流程並再次查詢狀態。

背景檢查發現已簽到時通常不顯示通知。發現尚未簽到時，每個自然日最多通知一次；如果開啟自動彈出驗證碼，會同時開啟驗證碼。

輪詢計時器會在上一輪檢查完成後才安排下一輪，因此網路請求較慢時，下一輪時間也會往後延。週期設定過短會增加請求數量，也可能觸發網站限流。

### 手動檢查

點選 `立即檢查/簽到` 後，會立即顯示 `檢查簽到狀態中……`。

- 帳號狀態為 `已登入` 時，優先共用或發送 `signinStatus`，不會無條件重新登入；
- 工作階段失效時，自動執行登入和狀態查詢；
- 憑據剛儲存或狀態為 `登入失敗` 時，會驗證已儲存的電子郵件和密碼；
- 發現尚未簽到後開啟驗證碼；
- 驗證完成後立即發送簽到請求。

簽到成功通知會包含耗時。之後腳本會並行查詢排名介面和使用者中心頁面，盡量顯示今日排名；排名查詢失敗不會撤銷已提交的簽到。

## 零點搶簽到模式

零點搶簽到模式不受「可簽到時自動彈出驗證碼」開關影響。即使自動彈出驗證碼已關閉，只要搶簽到模式開啟且符合頁面限制，腳本仍會準備驗證碼。

流程如下：

1. 腳本請求 BlogsClub 登入頁，讀取 HTTP `Date`，估算伺服器與本機的時鐘差。
2. 依照校準後的時間安排下一次伺服器零點。
3. 依照「搶簽到提前載入驗證碼」設定的時間（預設伺服器零點前 5 秒），同時啟動 Geetest 元件載入和 `signinStatus` 檢查。
4. 檢查完成並確認登入流程後，顯示驗證碼。零點前查到的狀態屬於前一天，不會用它跳過新一天的簽到。
5. 使用者在零點前完成驗證碼時，腳本會暫存驗證結果。
6. 到達校準後的伺服器零點，依照「搶簽到提交延遲」設定發送第一次 `action=signin`。
7. 尚未收到成功回應時，依照「搶簽到提交重試間隔」繼續發送，最多重試設定的次數；不等待前一個請求回應，任一次回應確認簽到成功後立即停止後續重試。
8. 如果完成驗證碼時已經超過目標提交時間，會立即開始第一次提交，不會等待精確的等號時刻。

計時器使用「目前伺服器時間已達到目標時間」的判斷。瀏覽器背景節流、系統睡眠或網路延遲造成計時器晚觸發時，不要求命中某個精確毫秒。

搶簽到模式只會在設定的次數和時間範圍內重試提交。多個請求可能同時進行；收到成功回應後不會再發起新的請求，但已發出的請求無法撤回。

如果另一個分頁或其他用戶端已經完成簽到，目前分頁仍可能提交一次，伺服器可能回傳「已簽到」或類似訊息。這是因為搶簽到在真正提交前不會再額外查詢一次狀態。

## API 與網路請求

腳本使用以下 BlogsClub 介面：

| 請求                                                | 用途                                              |
| --------------------------------------------------- | ------------------------------------------------- |
| `GET https://www.blogsclub.org/login.html`          | 取得登入 token，並讀取 HTTP `Date` 進行時鐘校準。 |
| `POST /index.php/getLogin`                          | 使用已儲存的電子郵件和密碼登入。                  |
| `POST /index.php/getProfile`，`action=signinStatus` | 查詢當日簽到狀態。                                |
| `POST /index.php/getProfile`，`action=signin`       | 提交 Geetest 驗證結果並簽到。                     |
| `POST /index.php/getProfile`，`action=signinRank`   | 查詢今日簽到排名資料。                            |
| `GET /usercenter.html`                              | 讀取目前使用者的 `blog_id`，用來比對排名。        |

這些請求都能在瀏覽器開發人員工具的 Network 面板中看到。Geetest 元件也會向 `static.geetest.com` 發送自己的驗證請求。

同一個頁面內，腳本只共用「正在進行中的」登入頁請求和簽到狀態請求；請求完成後立即清除，不快取舊狀態，也不在分頁之間共用。

## 權限與本機資料

腳本宣告的使用者腳本權限包括：

- `GM_xmlhttpRequest`：跨網域存取 BlogsClub 和 Geetest 資源；
- `GM_getValue`、`GM_setValue`：儲存帳號、設定和每日通知狀態；
- `GM_registerMenuCommand`、`GM_unregisterMenuCommand`：註冊使用者腳本選單；
- `GM_notification`：發送使用者腳本管理器或系統通知；
- `unsafeWindow`：存取頁面中的 Geetest 初始化函式。

`GM_notification` 的實際外觀由使用者腳本管理器和作業系統決定，腳本無法完全控制。

腳本使用非匿名請求，並沿用 BlogsClub 工作階段 Cookie。若要卸載腳本，且希望徹底刪除帳號資訊，請在使用者腳本管理器中清除這個腳本的儲存資料。

## 影響與已知限制

- 預設只在 BlogsClub 頁面發起檢查；腳本仍會匹配其他網頁，以便提供選單。
- 多個 BlogsClub 分頁各自擁有輪詢和搶簽到計時器，目前沒有跨分頁的主分頁選擇或鎖定機制。多個分頁可能同時彈出驗證碼，並各自發起設定的提交重試序列。
- 關閉「僅在 BlogsClub 頁面檢查」後，所有匹配網頁都可能發起輪詢和搶簽到流程。
- 搶簽到使用 HTTP `Date` 校準時鐘，但 HTTP 日期通常只有秒級精度，提交延遲設定是近似目標，不是伺服器保證的硬即時排程。
- offset 只校準時鐘差，不會從 HTTP `Date` 自動推斷業務時區；零點日曆使用腳本執行環境的本機時區。若瀏覽器時區與 BlogsClub 業務時區不同，搶簽到時間可能偏移。
- 驗證碼仍需人工完成。驗證碼過期、驗證失敗或元件載入失敗時，需要重新開啟並完成驗證。
- 排名介面通常只提供有限名次資料；使用者不在回傳範圍內時會提示未進入前 20 名，排名介面失敗不會影響簽到請求本身。
- 使用者腳本管理器、瀏覽器、系統睡眠、網路品質和網站限流都會影響檢查時機。

## 故障排除

### 一直顯示「已儲存」

`已儲存` 只表示憑據已寫入本機，不表示密碼驗證成功。點選 `立即檢查/簽到`，查看是否變為 `已登入` 或 `登入失敗`。

### 沒有彈出驗證碼

確認目前頁面屬於 BlogsClub，檢查「僅在 BlogsClub 頁面檢查」是否開啟；一般模式還要檢查「可簽到時自動彈出驗證碼」，或手動點選 `立即檢查/簽到`。搶簽到模式需要等到「搶簽到提前載入驗證碼」設定的準備時間。

### 看到多個驗證碼視窗

通常是多個 BlogsClub 分頁同時執行。關閉不需要的分頁，或暫時關閉零點搶簽到模式。

### 開發人員工具中沒有請求

預設限制開啟時，一般網頁不會傳送 BlogsClub 檢查請求。請在 BlogsClub 頁面查看 Network 面板，或關閉「僅在 BlogsClub 頁面檢查」。

## 隱私與安全提示

本腳本會儲存 BlogsClub 登入電子郵件和密碼，並使用它們執行自動登入。安裝前請確認腳本來源可信，也請確認自己接受將憑據用於 BlogsClub 登入介面。不要把包含本機憑據的使用者腳本管理器設定資料夾上傳或分享給他人。

## 開發

在儲存庫根目錄安裝相依套件後執行：

```bash
pnpm --filter blogsclub-signin-helper build
```

將使用者腳本建置產物寫入 `dist/`。

```bash
pnpm --filter blogsclub-signin-helper watch
```

在原始檔變更時重新建置使用者腳本。

```bash
pnpm --filter blogsclub-signin-helper dev
```

啟動支援 HMR 的 Vite 開發伺服器。

```bash
pnpm --filter blogsclub-signin-helper preview
```

先建置使用者腳本，再在本機啟動伺服器，提供產生的 `dist/` 產物。
